AutoLeads MVP

Product Requirements Document | September 2026

Status: MVP shipped and ready for user testing

Problem Statement

Small and medium-sized businesses (SMBs) in Brazil struggle to find high-quality, enriched sales leads in their target categories and geographies. They spend hours manually searching Google Maps, scraping Instagram, researching competitors, and crafting outreach messages. This is time-consuming, error-prone, and scales poorly.

AutoLeads automates lead discovery and enrichment, turning a 2-hour manual process into a 5-minute search, reducing API costs via smart deduplication, and providing sales-ready lead profiles with copy-to-contact options.

Vision & North Star

Enable sales and marketing teams at SMBs to discover, enrich, and contact high-potential leads in minutes, not hours. By 2027, AutoLeads should be the default lead-generation tool for category-based, location-targeted prospecting in Brazil.

Customer Value

  • Speed: From 2 hours to 5 minutes per search
  • Quality: Enriched with Instagram, competitors, scoring
  • Cost: Dedup cache saves API spend on repeat searches
  • Reusability: Global "Meus Leads" list for long-term prospecting

Business Metrics

  • Search velocity: Users complete 3+ searches/week
  • Lead quality: 70%+ leads actionable (have phone/website)
  • Dedup rate: 30%+ leads reused from cache (cost savings)
  • Retention: 80%+ of paying users active after 30 days

User Personas

🎯 Primary: Sales Manager (SMB)

Who: Manages 2-5 sales reps, needs consistent lead pipeline,

Pain: Manual lead sourcing is unpredictable; team spends 4+ hours/week googling competitors

Goal: Find 50+ qualified leads per month with minimal manual work

Success metric: Team closes 10%+ of exported leads within 30 days

💼 Secondary: Freelance Salesperson

Who: Solo seller or contractor, needs to build lists fast

Pain: Limited budget for expensive tools (HubSpot, Apollo); currently manual + LinkedIn

Technical Approach

Architecture: React frontend + Node.js/Express backend + Supabase PostgreSQL + external APIs (Google Maps, Instagram, Gemini, Discord)

Data Flow: User submits search → backend fetches Google Maps results (2 pages) → for each lead: check DB cache (dedup) → if new, enrich (Instagram + scoring + copy) → emit SSE progress → return results

Key Design Decision: Synchronous enrichment pipeline in request handler (not async job queue) to keep MVP simple; can migrate to Bull + Redis if search latency becomes issue at scale.

Cost Optimization: Deduplication cache means 30%+ of leads cost nothing (reused from DB). Instagram scraping is free (web scrape, no API key). Google Maps + Gemini are metered; queries are filtered before enrichment to minimize waste.

Acceptance Criteria for MVP Shipping

Functional

  • Search returns 5–15 results within 2 minutes
  • Enrichment (Instagram + scoring + copy) completes for 95%+ of leads
  • Discord notifications fire for hot leads (score ≥70)
  • Meus Leads displays all leads, filterable by temperature, paginated
  • Deduplication works: repeat locations skip enrichment, serve cached data

Quality

  • No 500 errors in backend logs (handled gracefully)
  • Frontend doesn't crash on large result sets (100+ leads)
  • All lead fields populated correctly (no null surprises)
  • Real-time progress updates display without lag

Testing

  • Tested with 3+ beta users; each runs 2+ searches
  • Manual walkthrough: search → dashboard → Meus Leads → export → contact
  • Verified: dedup cache hit (repeat search uses cached data), Discord notification fires
  • Error scenario: missing API key → graceful error message (not crash)
